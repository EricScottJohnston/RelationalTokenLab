# Relational Token Lab — Experiment 5

## System Grammar and Causal Transfer

This experiment is locked before seeing the result.

The target is not simple cross-domain analogy.

The hypothesis is that a model can learn a **domain-independent grammar of systems**
in a physical control domain and then reuse that grammar to reason causally in a
radically different administrative/legal institutional domain.

## Locked system ontology

```text
B  Boundary
P  Policy
T  Topology
G  Geometry
L  Level
R  Rate
C  Constraint
D  Delay
I  Information
```

Behavior is treated as the trajectory generated by the system, not as a primitive.

## Operational definition of causal reasoning

Given a system and a deliberate intervention, the model must identify:

1. which system role(s) changed directly;
2. whether topology changed, geometry changed, both, or neither;
3. which system roles can change downstream;
4. which roles remain invariant;
5. whether the nominated terminal level goes UP, DOWN, stays UNCHANGED, or is INDETERMINATE.

The experiment also contains **observations**. An observed change is not a causal
intervention and must not automatically generate a causal-delta signature.

## Domain A — physical fluid control

Mechanical training uses:

- tanks;
- pipes;
- pumps;
- valves;
- controllers;
- sensors;
- safety limits;
- response delays.

Examples distinguish changes such as:

```text
increase pump rate             -> Rate
increase existing line capacity -> Geometry
remove a pipe                  -> Topology
add liquid directly            -> Level
tighten a safety limit         -> Constraint
lose sensor access             -> Information
change the control rule        -> Policy
```

A policy can also induce a structural change.

Example:

```text
policy removes permission for a valve path
    -> Policy + Topology
    -> Geometry unchanged
```

versus:

```text
policy lowers capacity of an existing valve path
    -> Policy + Geometry
    -> Topology unchanged
```

## Domain B — administrative/legal institutional systems

The second domain contains no tanks, pipes, or pumps.

It uses:

- program jurisdiction;
- authority/referral relationships;
- review-channel capacity;
- pending queues;
- processing rates;
- statutory constraints;
- waiting periods;
- reporting/information;
- governing rules.

The same system roles exist at a more abstract institutional level.

## What transfers

After Domain-A training:

```text
system core
system-output heads
```

are transferred and **frozen**.

The administrative domain gets a fresh:

```text
vocabulary
word embeddings
sentence encoder
```

Only the new domain encoder is allowed to adapt in the transfer model.

## Controls

1. **Transfer**
   Intact mechanical system grammar, frozen.

2. **Scratch**
   Same system architecture, trained only on the administrative examples.

3. **Role-scrambled transfer**
   Same pretrained weight scale, but hidden-state recurrence is scrambled before
   freezing.

4. **Topology-blind transfer**
   Transferred system whose frozen output mapping cannot cleanly distinguish
   topology from geometry.

5. **Tiny transformer**
   Fresh transformer trained on the identical administrative examples.

## Few-shot training

Administrative label budgets are locked at:

```text
8
16
32
64
128
```

Administrative training examples contain only **single interventions**.

## Hard tests

### A. Hard single-intervention administrative test

Contains:

- policy-induced topology changes;
- policy-induced geometry changes;
- observations versus interventions;
- different surface phrasings.

### B. Compound-intervention test

Contains 2-3 simultaneous interventions.

The administrative model never sees compound interventions during training.

This asks whether the system grammar composes:

```text
Delta P + Delta T + Delta G
```

rather than learning each combination separately.

## Locked success criteria

At 32 administrative examples:

```text
Transfer - Scratch      >= 15 percentage points
Transfer - Transformer  >= 10 percentage points
```

On the hard administrative test:

```text
Exact system-role / causal-delta identification >= 90%
Topology-vs-geometry accuracy                   >= 95%
Affected-set micro F1                           >= 90%
Invariant-set precision                         >= 95%
Counterfactual direction accuracy               >= 90%
```

On unseen compound interventions:

```text
Complete causal-delta signature accuracy        >= 85%
```

The role-scrambled control must be at least 10 percentage points worse than intact
transfer on exact role/delta identification.

The report stores each criterion separately. Mixed results remain mixed.

## Run

Unzip this add-on into your existing `RelationalTokenLab` folder.

Activate the environment:

```powershell
.venv\Scripts\activate
```

Then run:

```powershell
python system_grammar_app.py
```

Leave the default settings unchanged and click:

**Run Experiment 5**

This is a heavier CPU experiment than Experiments 3 and 4 because five models are
trained at five administrative few-shot budgets.
